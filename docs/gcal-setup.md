# Google カレンダー連携 セットアップ手順

worklist3 の「📅 カレンダー登録」を使うための 1 回だけの準備。実装済みなので、
以下を済ませて Client ID / Calendar ID をアプリの 💾 メニューに入力すれば動く。

## 1. Google Cloud

1. プロジェクトを作成する。
2. **Google Calendar API** を有効化する。
3. OAuth 同意画面: **User type = External / 公開ステータス = Testing** のまま、
   **自分自身をテストユーザーに追加**する（この状態なら審査不要）。
4. スコープは **`calendar.events`** のみ。
5. **OAuth クライアント ID**（種別: ウェブアプリケーション）を発行する。
   - **承認済みの JavaScript 生成元**: `https://10-212-41-20.sslip.io`
     - 生 IP は生成元に登録できないため sslip.io 経由のホスト名を使う
       （`10-212-41-20.sslip.io` は `10.212.41.20` に解決される）。
   - （任意）手元の開発サーバーでも試すなら `http://localhost:5173` も追加する。
6. 発行された **Client ID** を、アプリの 💾 メニュー →「Google カレンダー連携」に入力する。

## 2. 専用カレンダー

1. Google カレンダーで **worklist 専用カレンダーを 1 本手動作成**する
   （普段使いの primary には書かない）。
2. その **カレンダー ID**（`xxxxx@group.calendar.google.com`）を同じ設定欄に入力する。

## 3. 稼働 PC（アクセス URL と証明書）

- アクセス URL を **`https://10-212-41-20.sslip.io`** にする。
- HTTPS 証明書をこのホスト名（SAN に含める）で用意し、利用するクライアント PC で信頼させる。
- GIS は非 localhost の生成元に HTTPS を要求するため HTTPS 必須。

## 動作

- 予定（開始時刻あり）を選択して「📅 カレンダー登録」。初回のみ同意画面、以降は画面なし。
- 同じタスクを再登録しても重複せず更新される（`gcalEventId` による upsert）。
- カレンダー側は削除しない方針。不要が溜まったら専用カレンダーごと消して再同期でよい。
- 「連携をリセット」はアクセストークンを破棄する（Client ID / Calendar ID は残る）。
