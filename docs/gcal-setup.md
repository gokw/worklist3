# Google カレンダー連携 セットアップ手順（初心者向け・ていねい版）

worklist3 の「📅 カレンダー登録」ボタンで、予定を Google カレンダーへ自動で書き込めるようにするための、
**最初の 1 回だけ**必要な準備です。少し手順は多いですが、1 つずつやれば必ず終わります。

> **この作業のゴール**
> 最後に手に入れたい「文字列 2 つ」を、worklist3 の 💾 メニューに貼り付けたら完成です。
> - **クライアント ID**（例: `1234567890-abcdefg.apps.googleusercontent.com`）
> - **カレンダー ID**（例: `abcd1234@group.calendar.google.com`）
>
> この 2 つを手に入れるのが、以下の作業のすべてです。迷ったらこのゴールを思い出してください。

---

## 最初に用語（ざっくりでOK）

| 言葉 | かんたんな意味 |
|---|---|
| **Google Cloud** | Google の開発者向け管理画面。ここで「アプリがカレンダーを触ってよい」という許可設定を作る。無料で使える。 |
| **プロジェクト** | Google Cloud の中の「作業フォルダ」のようなもの。1 つ作ればよい。 |
| **API を有効化** | 「このプロジェクトからカレンダー機能を使います」というスイッチを ON にすること。 |
| **OAuth（オーオース）** | 「このアプリにカレンダーを触らせてよいですか？」と Google があなたに確認する仕組み。初回に出る同意画面がこれ。 |
| **クライアント ID** | worklist3 を Google に見分けてもらうための、アプリの名札のような文字列。**人に見られても危険はない**値。 |
| **カレンダー ID** | 書き込み先のカレンダーを指す住所のような文字列。 |
| **スコープ** | アプリに許す操作の範囲。今回は「予定の読み書きだけ」に絞る。 |

> **安全性について**：長く保存すると危ないのは「アクセストークン」（一時的な鍵）だけで、これは worklist3 が
> パソコンのメモリ上に一時的に持つだけで保存しません。クライアント ID・カレンダー ID は保存しても問題ない値です。

---

## 全体の流れ（3 ステップ）

1. **Google Cloud 側**でクライアント ID を作る（← 手順が多いのはここ）
2. **専用カレンダー**を 1 個作って、そのカレンダー ID を調べる
3. worklist3 を動かしているパソコンの**アクセス URL と証明書**を整える

では順番に。

---

## ステップ 1：Google Cloud でクライアント ID を作る

ブラウザで [https://console.cloud.google.com/](https://console.cloud.google.com/) を開き、
worklist3 で使う Google アカウントでログインしてから始めます。

### 1-1. プロジェクトを作る

1. 画面上部の、プロジェクト名が出ているところ（初回は「プロジェクトの選択」）をクリック。
2. 右上の「**新しいプロジェクト**」をクリック。
3. 名前は何でもよい（例: `worklist3`）。「**作成**」を押す。
4. 数秒待つと作られます。作ったプロジェクトが選ばれているか、上部の表示を確認してください。

> **つまずき対策**：以降の作業は「今どのプロジェクトを触っているか」が大事です。
> 画面上部が `worklist3` になっているか、ときどき確認してください。

### 1-2. カレンダー機能（API）を有効化する

1. 左上の「☰」メニュー →「**API とサービス**」→「**ライブラリ**」を開く。
2. 検索欄に `Google Calendar API` と入力して、出てきたものをクリック。
3. 「**有効にする**」ボタンを押す。

これで「このプロジェクトからカレンダーを使える」状態になりました。

### 1-3. 同意画面を設定する（初回に出る「許可しますか？」の画面）

1. 左メニュー →「**API とサービス**」→「**OAuth 同意画面**」を開く。
2. **User Type** を聞かれたら「**外部（External）**」を選んで「作成」。
   - （組織アカウントで「内部」が選べる場合は内部でもよいですが、迷ったら「外部」でOK）
3. アプリ情報を入力：
   - **アプリ名**：`worklist3`（何でもよい）
   - **ユーザーサポートメール**：自分のメールを選ぶ
   - **デベロッパーの連絡先情報**：自分のメールを入れる
   - 他は空欄のまま「保存して次へ」
4. **スコープ**の画面：ここでは**何も追加せず**「保存して次へ」でOK。
   （アプリ側で `calendar.events` だけを要求するので、ここで足す必要はありません）
5. **テストユーザー**の画面：「**+ ADD USERS / ユーザーを追加**」を押し、
   **自分の Google アカウントのメールアドレスを追加**する。→「保存して次へ」。
6. 「概要」を確認して完了。

> **なぜテストユーザー登録が必要？**
> アプリを「公開ステータス = テスト中（Testing）」のまま使うと、Google の審査を受けずに済みます。
> ただし「テスト中」のアプリは、**テストユーザーに登録した人だけ**が使えます。
> 自分ひとりで使うので、自分を登録すれば十分です。**公開（本番）に切り替える必要はありません。**

### 1-4. クライアント ID を発行する（← ゴールの 1 つ目）

1. 左メニュー →「**API とサービス**」→「**認証情報（Credentials）**」を開く。
2. 上部の「**+ 認証情報を作成**」→「**OAuth クライアント ID**」を選ぶ。
3. **アプリケーションの種類**：「**ウェブ アプリケーション**」を選ぶ。
4. **名前**：`worklist3-web`（何でもよい）。
5. 「**承認済みの JavaScript 生成元**」の「**+ URI を追加**」を押し、次を入力：

   ```
   https://10-212-41-20.sslip.io
   ```

   > **これは何？** worklist3 を開く URL のことです。「この URL からのアプリだけ許可する」という設定で、
   > 安全のために必要です。**入力した URL と、実際にアプリを開く URL が 1 文字でも違うと動きません**
   > （`http` と `https`、末尾の `/`、ポート番号の有無まで一致させる必要があります）。
   >
   > **なぜ変な URL？** Google は「生の IP アドレス（`10.212.41.20`）」を、この欄に登録させてくれません。
   > そこで `sslip.io` という無料の仕組みを使います。`10-212-41-20.sslip.io` は自動的に `10.212.41.20`
   > に変換されるホスト名で、IP を「ホスト名の形」にしただけのものです。
   >
   > （任意）手元でも試したい場合は、同じ要領で `http://localhost:5173` も追加しておくと、
   > 開発サーバーでも動作確認できます。

6. 「**作成**」を押す。
7. **クライアント ID** が表示されます（`……apps.googleusercontent.com` という文字列）。
   これをコピーして、あとで worklist3 に貼るためにメモしておきます。
   - 一緒に「クライアント シークレット」も表示されますが、**worklist3 では使いません**。無視してOK。
   - この ID は後からでも「認証情報」の一覧でいつでも確認できます。

**これでゴールの 1 つ目「クライアント ID」が手に入りました。**

---

## ステップ 2：専用カレンダーを作って、カレンダー ID を調べる（← ゴールの 2 つ目）

普段使っているカレンダー（primary）に直接書き込むと、消したいときに大変です。
そこで **worklist3 専用のカレンダーを 1 個**作り、そこにだけ書き込みます。
（いらないイベントが溜まっても、このカレンダーごと消して作り直せば掃除できます）

### 2-1. 専用カレンダーを作る

1. [https://calendar.google.com/](https://calendar.google.com/) を開く。
2. 左側の「**他のカレンダー**」の横の「**+**」→「**新しいカレンダーを作成**」。
3. 名前を付ける（例: `worklist3`）。「**カレンダーを作成**」を押す。

### 2-2. カレンダー ID を調べる

1. 左側のカレンダー一覧で、いま作った `worklist3` にマウスを乗せ、
   出てくる「⋮（縦の三点）」→「**設定と共有**」を開く。
2. 少し下にスクロールすると「**カレンダーの統合**」という欄があります。
3. その中の「**カレンダー ID**」に、`……@group.calendar.google.com` という文字列があります。
   これをコピーしてメモします。

**これでゴールの 2 つ目「カレンダー ID」が手に入りました。**

> **メモ**：自分で作ったカレンダーなので、アプリ側の許可（スコープ）は「予定の読み書き」だけで足ります。
> カレンダーそのものを作る強い権限は要りません。

---

## ステップ 3：worklist3 を開く URL と証明書を整える

worklist3 を動かしているパソコンで、次を用意します（IT に少し詳しい人向けの作業です）。

1. worklist3 を開く URL を **`https://10-212-41-20.sslip.io`** にする
   （以前の `https://10.212.41.20` から変更）。ステップ 1-4 で登録した URL と**完全に一致**させます。
2. この URL は **HTTPS（鍵マーク）** である必要があります。Google のログイン部品は、
   `localhost` 以外では HTTPS を必須にしているためです。
3. `10-212-41-20.sslip.io` という名前向けの **HTTPS 証明書**を用意し、
   使うパソコン（クライアント側）で**信頼済み**にします（証明書の「SAN」にこのホスト名を含める）。

> **なぜ HTTPS と証明書が要る？** Google のログイン画面を安全に表示するための決まりです。
> ここは worklist3 のコードではなく、サーバーの立て方の話なので、環境に合わせて用意してください。
> 自己署名証明書を使う場合の具体的な信頼手順は、別途の運用メモにまとめる想定です。

---

## 仕上げ：worklist3 に 2 つの ID を入力する

1. `https://10-212-41-20.sslip.io` で worklist3 を開く。
2. 右上の「**💾 ▾**」メニューを開く。
3. 「**Google カレンダー連携**」の欄に、メモした 2 つを貼り付ける：
   - **Client ID** … ステップ 1-4 のクライアント ID
   - **Calendar ID** … ステップ 2-2 のカレンダー ID
   - 入力すると自動で保存されます（保存ボタンはありません）。

---

## 使い方

1. 「**予定のみ**」トグルを ON にすると、開始時刻の入った予定だけが並びます。
2. 登録したい予定を選ぶ（行の左のチェック、または `Space` キー。まとめて選ぶなら「全選択」）。
3. 上部の「**📅 カレンダー登録 (件数)**」を押す。
4. **初回だけ**、Google の同意画面が出ます。自分のアカウントを選んで「許可」。
   - 「このアプリは Google で確認されていません」と出ることがありますが、**自分が作ったアプリなので問題ありません**。
     「詳細」→「（アプリ名）に移動」で進めます。
5. 2 回目以降は画面が出ず、そのまま登録されます。
6. 終わると「新規 / 更新 / 時刻なし / 失敗」の件数が表示されます。

### 覚えておくと安心なこと

- **同じ予定をもう一度登録しても、二重になりません**。既存のイベントが最新内容に更新されます。
- カレンダー側でイベントを手で消してしまっても、もう一度登録すれば**作り直されます**。
- worklist3 側で予定を消しても、**カレンダー側は自動では消えません**（残ります）。
  いらないものが増えたら、専用カレンダーごと消して作り直すのが手軽です。
- 「時刻なし」でスキップされたものは、開始時刻を入れてからもう一度登録すれば入ります。
- 「連携をリセット」を押すと、一時的な鍵（アクセストークン）を捨てます。
  Client ID・Calendar ID は消えません。次回また同意し直せます。

## うまくいかないとき（チェックリスト）

| 症状 | 見るところ |
|---|---|
| ボタンを押すと「Client ID / Calendar ID を設定してください」と出る | 💾 メニューの 2 つの入力欄が空。ステップ 1-4・2-2 の値を貼る |
| 同意画面で「アクセスをブロック」「redirect_uri / origin mismatch」等のエラー | ステップ 1-4 の「承認済みの JavaScript 生成元」と、いま開いている URL が**完全一致**しているか（`https`、末尾スラッシュ、ポート）。`https://10-212-41-20.sslip.io` で開いているか |
| 「このアプリは確認されていません」で先に進めない | 「詳細」→「（アプリ名）に移動」。自分のアプリなので安全。加えて、同意画面の**テストユーザーに自分のメール**が入っているか（ステップ 1-3） |
| 鍵マークが出ない／証明書の警告 | ステップ 3 の HTTPS と証明書。ホスト名 `10-212-41-20.sslip.io` 向けの証明書を、使う PC で信頼させる |
| 「失敗」件数が出る（403） | 権限不足かレート超過。少し待って押し直す。Calendar ID が専用カレンダーのものか確認 |
| 登録したのにカレンダーに出ない | 書き込み先が専用カレンダー。Google カレンダー左の一覧で、その専用カレンダーの表示が ON か確認 |

困ったら、まず「**開いている URL がステップ 1-4 で登録した URL と一字一句同じか**」を疑うのが近道です。
ここのズレが、初回設定でいちばん多いつまずきです。
