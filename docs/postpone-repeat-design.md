# 延期・繰り返しの強化 設計メモ(#37 + #30)

現状の延期・繰り返しを、営業日(土日祝を避ける)対応・複数タスク一括・
月次/年次の日付指定へ広げるための設計。#37 と #30 の重なる部分をまとめて扱う。

## 対象 Issue
- **#37 延期機能のパワーアップ**
  - 対象は「選択したタスク」。タスクを選択して延期キー(P)を押したときの動作。
  - 繰り返しのないタスクも翌日へ延期できるように。
  - 土日祝を飛ばして延期先を決める(例: 金で延期 → 月)。
  - 繰り返しも、次回が休日なら次の該当日へ(例: 毎週木で来週木が祝日 → 翌週の木)。
- **#30 予定設定と延期先の修正**
  - ① 毎月X日 / 毎年X月X日 の繰り返し設定。
  - ② 延期先が土日祝のときの延期方法修正(= #37 の休日回避と同じ土台)。

## 全体像:4つのブロック

### A. 営業日ユーティリティ(共有の土台)
`src/lib/date.ts` に追加する純関数群(テスト対象)。

- `isWeekend(dateStr): boolean` — 土日判定。
- `isHoliday(dateStr, holidays: Set<string>): boolean` — 祝日判定。
- `isBusinessDay(dateStr, holidays): boolean` — 平日かつ非祝日。
- `rollToBusinessDay(dateStr, holidays, dir = +1): string`
  — その日が休日なら、方向 dir(既定は前へ=未来)へ営業日になるまでずらす。
  「金→月」はこれで実現(土=+1→日→月)。

祝日データ源(**決定済み: 内蔵リスト**):
- `src/lib/holidays.ts` に `Record<year, string[]>`(YYYY-MM-DD)。**当面 2026–2029 を収録**。
  オフラインで確定的・テスト容易。範囲外の年は「祝日なし(土日のみ回避)」にフォールバック。
  収録年が切れる前に追記する運用(ファイル冒頭に更新方法をコメントで明記)。
- 将来の拡張候補として Google カレンダーの「日本の祝日」取得があるが、今回は対象外。

回避の既定(**決定済み: 常に回避**):
- 土日・祝日はいずれも常に回避する。ON/OFF 設定は設けない(実装をシンプルに保つ)。

### B. 延期の拡張(#37 本体)
`postponeTask` を作り直し、`handlePostpone` を複数選択対応にする。

- **対象の選び方**(H/L と揃える):
  - 選択があれば選択タスク全部、無ければカーソル1件。
- **繰り返しなしタスク**: 「翌営業日」へ。
  = `rollToBusinessDay(addDay(date, +1))`(翌日にして、休日なら次の営業日へ)。
  → 金曜のタスクを P で延期 = 月曜。
- **繰り返しありタスク**: 次回日程へ延期(現状踏襲)＋休日回避(下記 D の戦略で調整)。
- 実績・待ちはクリア(現状どおり)。期限は移動日数分ずらす(現状どおり)。
- undo・カーソル追従は既存の仕組みを流用
  (`pushUndo` + `armRefocusIfLeaves`。#36/#31 で導入済み)。
- 「一日の終わりに残りを翌日へ一括」= 残タスクを選択 → P、で実現(専用ボタンは作らない)。
- 現状の「繰り返しのみ延期可」という制限メッセージは撤廃。

### C. 月次/年次の日付指定(#30①)
`RepeatConfig` を拡張。

```ts
interface RepeatConfig {
  mode: "schedule" | "afterComplete";
  unit: "day" | "week" | "month" | "year";
  interval: number;
  weekdays?: number[];      // 週:曜日指定(既存)
  dayOfMonth?: number;      // 月:毎月X日(1–31)。新規
  month?: number;           // 年:X月(1–12)。新規(dayOfMonth と併用)
  copyPlanStart: boolean;
}
```

- **毎月X日**: unit=month, interval=1, `dayOfMonth=X`。
  次回日 = 基準日の翌月(interval 月後)の X 日。
- **毎年X月X日**: unit=year, interval=1, `month=M, dayOfMonth=D`。
- **月末クリップ**(要決定): X=31 で 2月・30日月のときは「その月の末日」に丸める案を推奨。
- 未指定(dayOfMonth 無し)は現状どおり「基準日の日を維持して N か月/年後」。
- TaskForm の繰り返しUIに、unit=month/year のとき日・月の入力欄を出す。

### D. 繰り返し次回日の休日回避戦略(#30② と #37 の繰り返し部分)
「どうずらすか」は繰り返しの定義軸で変える。丸め方向は対象の性質で分ける
(延期=作業を後ろへ送る / 固定日=締め・支払いアンカーで“その日までに”)。

- **曜日ベース**(週の weekdays 指定): その曜日を保ったまま、休日なら次の該当日へ。
  例: 毎週木で来週木が祝日 → **翌週の木**(金へ丸めない)。
  実装: `nextWeekdayAfter` で得た日が休日なら、さらに 1 週間進めて再判定。
- **固定日**(毎月X日 / 毎年X月X日 = dayOfMonth/month 指定): 算出日が休日なら
  `rollToBusinessDay(dir = -1)` で **前営業日** へ前倒し。
  例: 毎月25日が日曜 → **23日(金)**。毎月1日が土曜 → 前月末の営業日。
  (日本の支払い・締め切りの商慣行に合わせる。切替オプションは設けない=既定のみ)
- **N日ごと / 単純な月・年後**(dayOfMonth 指定なし): **休日回避しない**(下記ドリフト対策)。
- **延期(P)**: 常に **翌営業日**(dir = +1)。作業を後ろへ送る操作のため。
- `generateNextOccurrence`(完了時の次回生成)と `postponeTask`(延期)の両方に適用。

### E. エッジケース・ループ対策(重要)
素朴に「丸めた実日付」を次回計算の基準にすると破綻するため、以下を必須とする。

1. **日付ドリフト対策(固定日)**
   丸めた `task.date` を基準に翌月を計算すると、月ごとにズレが累積する。
   例:毎月1日で 8/1(土)→前営業日 7/31 に丸め → 次回を 7/31+1ヶ月=8/31 と誤算出。
   **対策**: 固定日の次回は実日付ではなく **名目日(dayOfMonth/month)から計算**する。
   丸め幅(最大でも数日)は月長(28日以上)より十分小さいので、`task.date` に最も近い
   dayOfMonth の日=名目日として一意に復元でき、そこに interval を足して丸め直す。
   → 名目日を別フィールドで保存する必要はない。年次も month+dayOfMonth で同様。

2. **周期タスクは回避しない(ドリフト源を断つ)**
   dayOfMonth も weekdays も無い「N日ごと / 単純な月・年後」は、丸めると毎回ズレて
   ①と同じ暴走になる。これらは周期(◯日ごと)重視なので **休日回避の対象外**にする。

3. **曜日ベースはドリフトしない**
   毎週◯曜は「同じ曜日のまま +1 週」だけ動かすので、`task.date` は常にその曜日に載る。
   実日付を基準にしてよい(復元不要)。

4. **丸めの停止保証(ループ防止)**
   `rollToBusinessDay` は上限回数(例: 31)を設け、超えたら丸めずに元日を返す
   フォールバックにする。祝日データ不整合でも無限ループしない。
   **フォールバック時のメッセージは出さない(サイレント)**。現実には起きず、
   ユーザーがその場で直せる事象でもなく、一括延期ではトーストがスパムになるため。
   (将来どうしても診断が要るときだけ console.warn を足す余地は残す)

5. **延期は必ず前進(同日復帰なし)**
   延期は翌日にしてから前方へ丸めるだけなので、結果は必ず元日より後。
   「翌日が祝日だから同じ日に戻る」は起きない(前方一方向のため)。
   固定日の前営業日丸めも、次回名目日(基準+interval)は現在日より十分先(≥約3週)なので、
   前倒し(最大数日)しても過去日や現在日に戻ることはない。

## 決めたこと(設計判断)
1. **祝日データ源**: 内蔵リスト(`src/lib/holidays.ts`)。当面 **2026–2029** を収録。→ 決定
2. **回避の既定**: 土日・祝日とも **常に回避**(ON/OFF 設定は設けない)。→ 決定
3. **非繰り返し延期の定義**: 「翌営業日」で確定(翌日にして休日なら次営業日)。→ 推奨のまま採用
4. **月末クリップ**: 存在しない日(毎月31日など)は「その月の末日へ丸め」。→ 推奨のまま採用
5. **H/L の単日移動**: 休日回避は効かせない(P/繰り返しのみ対象。H/L は精密な手動操作)。→ 推奨のまま採用
6. **固定日(毎月X日/毎年X月X日)の丸め方向**: **前営業日(前倒し)**。切替オプションは設けず既定のみ。→ 決定
7. **丸め方向のまとめ**: 延期(P)=翌営業日 / 固定日=前営業日(名目日から再計算)/ 曜日ベース=同曜日で次の該当日 / N日ごと・単純な月年後=**回避しない**。
8. **ループ・ドリフト対策**: 固定日は名目日基準で再計算(実日付を基準にしない)/ 周期タスクは回避対象外 / `rollToBusinessDay` は上限回数でフォールバック。→ セクションE 参照。
